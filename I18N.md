# Gupax i18n framework

## What this version adds

**This version adds multi-language support to Gupax.** It introduces a
lightweight i18n layer and routes every user-visible string through it, so the
UI can be translated without touching any UI code.

- A `Language` enum, per-language translation registry, and `tr()` /
  `tr_ref()` / `tr_format()` lookups with automatic English fallback
- `t!("...")` and `t_f!("... {}", arg)` macros covering the whole UI
- A language selector in the bottom bar that only appears once a second
  language is registered
- Tests that enforce placeholder parity, registry completeness and duplicate
  key safety
- This tree ships the **framework only**: no translations or extra fonts are
  bundled, so the binary behaves exactly like the upstream English build until
  a language table is added

This tree ships the **i18n framework only**: the app behaves exactly like the
upstream English build (no translations and no extra fonts are bundled), but
all user-visible strings already go through translation calls, so a language
can be added without touching any UI code.

## How it works

- `ui.label(t!("Save"))` — static string, falls back to the English source
  when the current language has no entry.
- `t_f!("Stop {}", name)` — template with ordered `{}` placeholders.
- `tr_ref(&string)` — translate a runtime-built label.
- English text is the key. Missing keys always fall back to English, so a
  partially translated language never shows blanks.

## Layout

```
src/utils/i18n/
└── mod.rs   # Language enum, registry, tr()/tr_ref()/tr_format(), t!/t_f!
```

## Adding a language

1. Add a variant to `Language` and fill in:

   ```rust
   pub enum Language {
       #[default]
       English,
       SimplifiedChinese, // example
   }

   impl Language {
       pub const fn native_name(self) -> &'static str {
           match self {
               Self::English => "English",
               Self::SimplifiedChinese => "简体中文",
           }
       }
       pub const fn code(self) -> &'static str {
           match self {
               Self::English => "en",
               Self::SimplifiedChinese => "zh-CN",
           }
       }
   }
   ```

2. Create `src/utils/i18n/zh_cn.rs`:

   ```rust
   pub static PAIRS: &[(&str, &str)] = &[
       ("Save", "保存"),
       ("P2Pool is offline", "P2Pool 已离线"),
       // ...
   ];
   ```

   The English side must match the `t!("...")` source **character for
   character** (spaces, quotes and escapes included).

3. Register the table:

   ```rust
   static TABLES: &[(Language, &[(&str, &str)])] = &[
       (Language::English, &[]),
       (Language::SimplifiedChinese, zh_cn::PAIRS),
   ];
   ```

4. Optional: add a font for languages the default fonts cannot render (CJK,
   Arabic, ...):

   ```rust
   static BYTES_NOTO_SC: &[u8] = include_bytes!("../../../assets/fonts/NotoSansSC-Regular.otf");

   impl Language {
       pub const fn font(self) -> Option<&'static [u8]> {
           match self {
               Self::English => None,
               Self::SimplifiedChinese => Some(BYTES_NOTO_SC),
           }
       }
   }
   ```

   `install_fonts()` appends the font to the `Proportional` and `Monospace`
   families as a glyph fallback only, so the English rendering does not
   change.

5. Optional: follow the system language on first start. `state.gupax.language`
   uses `#[serde(default)]`, and `Language::default()` is English; a
   `detect_system_language()` helper (for example with the `sys-locale` crate)
   can resolve a locale prefix to a variant.

6. Run `cargo test`. The framework enforces:

   - every non-English `Language` variant has a registered table
   - translations keep the same number of `{}` as their English key
   - no empty values and no conflicting duplicate keys

Untranslated keys fall back to English, so translations can be submitted in
batches.

## Language selector

The bottom bar shows a language menu only when more than one language is
registered (`i18n::has_language_choice()`). Switching a language calls
`set_language()` and re-installs fonts immediately; the choice is persisted in
`gupax.toml` (`gupax.language`).

## Known limitations

- The tray menu is built once by the OS; a language change applies after a
  restart.
- CLI `--help` and daemon output are parsed/printed before the UI language is
  loaded and stay English.
- `t_f!` supports ordered `{}` placeholders only; languages with complex
  plural rules need a different lookup strategy (for example ICU4X).
- Right-to-left layouts are not mirrored yet (text shaping itself works).
- Number/date formatting still uses English grouping.
